プロローグ：SQLの基本4つの呪文

正規化によって綺麗に整理されたデータベースのテーブル。
アオキは、実際にこれらのテーブルからデータを抽出したり、更新したりするためのデータベース操作言語 **SQL** を学び始めた。
アオキ
「SQLって、データを操作するための専用コマンドなんですね。基本になるコマンドはどんなものがあるんですか？」
ヤマモト
「フン、アオキ。基本は4つだ。データを検索する **`SELECT`**、追加する **`INSERT`**、更新する **`UPDATE`**、削除する **`DELETE`**。これらを組み合わせてデータベースを動かすんだ」
-- 会員テーブルから名前を検索
SELECT 名前 FROM 会員 WHERE 会員ID = 'M001';

-- 新しい会員を追加
INSERT INTO 会員 (会員ID, 名前) VALUES ('M003', 'ミズダイ');

-- データを更新
UPDATE 会員 SET 名前 = 'アオキ改' WHERE 会員ID = 'M001';

-- データを削除
DELETE FROM 会員 WHERE 会員ID = 'M003';
アオキ
「SELECT、INSERT、UPDATE、DELETE。英語の動詞そのままなので直感的ですね！」

2つの表を繋ぐ魔法（テーブルの結合 - JOIN）

アオキ
「でも、正規化でテーブルを『会員テーブル』と『所属クラステーブル』にバラバラに分けたじゃないですか。これらを組み合わせて『アオキさんはどのクラスに所属しているか』という情報をまとめて一覧表示したいときはどうするんですか？」
ホシノ
「そういう時こそ、**`JOIN`**（結合）を使います。2つの異なるテーブルを、共通の列（キー）を仲介役にして1つに繋ぎ合わせる魔法の呪文です」
ヤマモト
「最もよく使われるのが **`INNER JOIN`（内結合）** だ。両方のテーブルに存在する共通データだけを結びつけて抽出する。もし、片方にしかデータがない行も強制的に残したい場合は **`LEFT OUTER JOIN`（左外部結合）** などを使うんだ」
SELECT 会員.名前, クラス.クラス名
FROM 会員
INNER JOIN クラス ON 会員.クラスID = クラス.クラスID;
ミズダイ
「なるほど！ 筋肉の結合（JOIN）だな！
『骨テーブル』と『筋肉テーブル』を、関節という共通キーで結合させることで、初めて『関節を動かす（動作ログ出力）』という1つの強力な処理（レコード）が完成するのだ！」
アオキ
「結合が外れたら大怪我ですけど、要するに共通のIDで複数の表を合体させて、必要なレポートを瞬時に作成する技術が `JOIN` なんですね！」

午前問題（科目A）にチャレンジ！

SQLの基本命令とテーブル結合の概念を理解したアオキ。
ホシノさんがホワイトボードに、SQLに関する午前過去問を書き出した！
【問題1】
関係データベースにおいて、2つのテーブルを特定の列の値に基づいて結びつけ、1つのテーブルのように扱うためのSQL句はどれか。

ア：GROUP BY
イ：ORDER BY
ウ：JOIN
エ：HAVING
アオキ
「テーブルを共通の列で結びつける命令だから、正解は **『ウのJOIN』** です！」
ホシノ
「大正解です！ ちなみに、GROUP BYはグループ化、ORDER BYは並び替え、HAVINGはグループ化後の絞り込みを行う句になります」
【問題2】
テーブル「社員」から、部署コードが「D01」であるレコードの「社員名」を取得し、さらにそれを社員名の昇順（五十音順など）で並べるための適切なSQL文はどれか。

ア：SELECT 社員名 FROM 社員 WHERE 部署コード = 'D01' ORDER BY 社員名 ASC;
イ：SELECT 社員名 FROM 社員 WHERE 部署コード = 'D01' GROUP BY 社員名;
ウ：UPDATE 社員 SET 社員名 WHERE 部署コード = 'D01';
エ：SELECT 社員名 FROM 社員 HAVING 部署コード = 'D01' ORDER BY 社員名 DESC;
ヤマモト
「アオキ、これが分からないならお前の頭の中のデータベースを全削除（DROP DATABASE）してやる。答えを言え」
アオキ
「頭を初期化しないでください！ データを検索するのがSELECT、条件がWHERE、並び替えの昇順（ASC）だから、正解は **『ア』** です！」
ホシノ
「素晴らしい、大正解です！ 並び替えは ORDER BY を使い、昇順は ASC (Ascending)、降順は DESC (Descending) となります」
ミズダイ
「ガハハ！ SQLもバッチリだな！ データを思い通りにコントロールする『SQLマッスル』がビルドされたぞ！ よし、今日の仕上げに……」
ヤマモト
「フン、プロテイン摂取（INSERT）のタスクを実行する。……（ごくごく）チッ、やはり最高だな。アオキ、データベース編（第5段階）も終わりだ。次は試験の最難関である第6段階『アルゴリズム』だ。地獄を見せてやるから覚悟しておけよ」
アオキ
「（言うことがいちいち怖いけど、ヤマモトさんの解説は本当に分かりやすいな……）よし、アルゴリズムも気合を入れて頑張ります！」
SQLを用いたデータベース操作法を学び、ロードマップ第5段階「データベース」を完全クリアしたアオキ。
いよいよ試験の合否を分ける難関、第6段階「アルゴリズム（疑似言語・探索・ソート）」へと進んでいく！
